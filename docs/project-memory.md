# 项目记忆（开发中）

项目模式开关 `projectMemory: true`，**默认关闭**，关闭时行为与旧版一致。它不会自动迁移旧库，也不会把旧库当个人记忆；需要带走历史时显式运行 `scripts/migrate-to-personal.mjs`（只复制、不删除源库、可重复执行、跳过已取代与已删除条目）。

- `mcp__lm_personal__memory_*` 访问独立的个人通用库，`mcp__lm_project__memory_*` 访问当前会话的项目库。两库的数字 ID 各自独立；所有写入、召回、来源、反馈、修正、删除、置顶等记忆工具走同一路由。
- 项目身份使用会话创建时的宿主目录解析出的真实 Git checkout 根，不由工具参数、当前 shell cwd 或仓库名决定。同名仓库、不同 checkout 分开；嵌套仓库使用自身根。当前实现按物理路径识别，移动 checkout 不会自动关联旧的库。
- 新会话第一次项目调用以原子操作绑定项目，持久保存；之后只接受同一绑定。旧的未绑定会话、fork、子 Agent、非 Git 位置或无可信会话不能访问项目库。不退回旧全局库。此约束针对插件入口，不限制用户或 Agent 通过其余宿主文件权限直接访问本机文件。
- 项目模式不启动旧 MCP、旧全局捕获或 Viewer；用对应作用域的工具管理。绑定成功后，停会/销毁时的捕获和变更推送只用当前项目目录。项目模式默认不外发，只有明确设置 `allowRemote: true` 且系统未禁外发才允许投递提炼作业。个人库只走显式工具。手工配置的其他 MCP 或共享 `current.md` 注入不是此插件所能撤销，测试 profile 不得同时启用它们。
- 项目自动召回仍默认关闭；显式开启、会话 ID 在名单内且允许模型上下文外发时，仅读当前绑定项目并提示项目工具及编号，不扫个人库、不续租。安装版探针已在同样授权的 A/B 会话中问同一个锚点，只有拥有该记忆的 A 收到提示。**真实模型下的任务收益仍未验证**，所以门禁不达标就保持关闭。
- `confirmedOutcomes: true`（默认关闭）允许用户把紧邻上一条助手回复的完整一行逐字写成 `确认结论：原句` 或 `确认修复：原句`，分别存为项目事实或经验。只存该行和用户确认原话，不转发确认消息给提炼模型，不读取或自动采信工具输出。来源证明的是用户确认，不是系统独立验证。安装版探针已验证真实项目续聊后的修复入库，另一项目查不到。

## 有效日期与跨会话修正

可以在确认事实时显式传 `memory_remember({kind:"fact", ..., valid_from:"2024-01-01"})`。后来发现事实**发生变化**，用当前编号、`expected_version` 和 `effective_from` 调用同库 `memory_correct`；旧事实到生效日停止有效（不含当日）。如果旧说法**本来就错了**，只修正内容，不传 `effective_from`：错误版本不会进入可查询的有效历史，新版继承有效起点。`event_date` 仍是事件／观察日，不被当作有效日期。

按已知当前事实的编号执行 `memory_recall({id, as_of:"2024-01-31"})`，可查当日唯一有效的版本。默认召回不暴露历史；未声明区间、无唯一结果、已删除链或早于有效起点时不猜。这里用显式修正链接同一事实；跨会话只做**字面归一**（忽略大小写、全半角、标点和空白）与**用户确认的佐证**，不推断同义改写、不推断时间、不补齐缺失证据。

## 归一、补证与自动召回的验收

- **事实归一**：同一库内，大小写、全半角、标点和空白不同但措辞相同的同 kind 主张只存一条，第二句不再新增行；措辞不同（哪怕只多一个词）视为不同主张，不合并、不猜测。
- **跨会话补证**：第二个会话以 `确认结论：原句` 确认同一事实时，不覆盖第一条，而是给该条追加一条带来源原话的佐证记录；`memory_source` 的 `corroborations` 可查。同一会话重复确认不算独立佐证。佐证会随硬删除一起清除。
- **自动召回门禁**：实验事件写入各库 `task-recall-events.jsonl`（只含会话、候选编号和结果，不含用户文本，超过 1 MiB 停止追加）。`node scripts/eval/task-recall-gate.mjs <绝对库路径>` 用事件和 `log.jsonl` 的反馈计算门禁：≥20 次提示、≥10 个有反馈的候选、有用率 ≥80%、无用 ≤1。未达标即保持默认关闭，这是当前状态。
- `node scripts/eval/task-recall-replay.mjs` 在临时 SQLite 上对冻结测试记忆做确定性回放，量的是命中与误报，不是回答质量：字面锚点 5/5 命中且指向正确；5 个负例（无回溯信号、无锚点、退出语、疑似凭据、双条歧义）零误报；改述型问题全部弃权（这是当前词面匹配的覆盖上限）；单条提示 215 字节。

- `node scripts/eval/dsh-project-memory-smoke.mjs` 用已安装的 DSH、临时 HOME、两个真实 Git 仓库及 loopback 模型协议桩，验证首次工具发现、A/B 同号读写、个人库跨项目读取和旧全局库未打开。
- `node scripts/eval/dsh-package-smoke.mjs <包.tgz>` 验证**打包产物**本身（含迁移脚本随包发布）：解包后装进 profile 的 `node_modules`，由已安装 DSH 加载，项目工具注册、写入与召回往返成功，且不生成旧库。
- `node --test tests/migrate-personal.test.mjs` 验证迁移只带 active 条目、保留事件日期与置顶、重复执行为幂等、源库不被改动。
- 真实模型：用 `glm-5.3-flash` 对一段真实发布流程对话做提炼，产出 2 条经验 + 1 条会话摘要，经统一提交入口入库后可按「发布流程 暂存验收」「完整回归」召回，日期与来源均在。

## 冲突裁决接口（0.19.4）

`POST /api/conflict/resolve`（viewer，owner-only）三档判定：`adopt`（旧条逻辑删除并记 superseded）、`keep`（记 related，内容不动）、`unrelated`（记 unrelated，不再提示）。加固项：判定白名单；裁决前重校验该对仍是规则候选（409 否决）；支持 `expected_old_version` 乐观并发；成功后写 `log.jsonl` 审计（`conflict_resolve`）。

## 冲突扫描收紧（0.19.1）

真库实证：`#339`（配图形态决策）与 `#262`（变更热流上线）这类条目会被旧规则判成「冲突待裁」。

- **状态词不再算取代**：`显式引用` 分支原先用宽泛的完结词表（含「已上线／已修复／已完成」）。`#360` 写「变更热流已上线（#262）」是在给 `#262` 作证，却被当成「#262 已被取代」。现在该分支只认替换类动词（取代／替代／作废／弃用／废弃／下线／不再使用／收编／退役）。
- **括注不再跨条目命中**：取代词必须落在「这条引用自己」的括注内（从引用末尾到下一条引用之前）。`#339` 的「相关：id=319（Agnes 弃用）、id=320 v3（配图惯例）、id=338、id=336」用固定 ±40 窗口时，319 的「弃用」会命中后面每一条 id，凭空造出三对误报。
- 真实库效果：候选对 12 → 8，引用型全部消失；剩余 8 对都是高相似 + 新条带取代词，仍需模型复核或人工判断，规则本身不判真伪。
