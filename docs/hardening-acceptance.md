# 可靠性修复验收（未发布）

目标是修复 2026-11-17 评审发现的工程故障，并建立进入下一轮检索质量优化的可审计基线。尚未证明达到任何竞品梯队。生产库未被本轮运行、迁移或写入。

## 已实现

- 当前包 worker 唯一路径，禁止数据目录旧 worker 优先绕行。
- 提炼任务持久化成功后才登记采集完成；派发失败相同输入可重试。
- 保留消息日期标记，未知日期不以采集日替换；日期换算的真实模型准确率仍待验证。
- 共享 SQLite 文件锁覆盖队列生产/消费；进程崩溃自动释放；current.md 加锁并原子替换。
- 主写入查重放在 BEGIN IMMEDIATE 内；手动纠正在事务内重查版本/状态。
- 遗忘续租使用 used_count/last_used_at，只有 memory_feedback useful=true 更新；旧 hit_count 仅保留曝光统计。
- 删除/修正保留规范化内容 SHA-256 阻断自动同文复活；手动 remember 不被阻断。摘要不是介质级擦除，语义改写复活不在保证范围。
- 自动条目保存模型实际看到的已脱敏输入窗口与消息序号，memory_source 回查；有来源不等于主张语义已验证。旧条目不伪造来源。
- 同会话、同 kind、更新 revision 的明确纠正可以附 supersedesId 和原文引文取代旧条；非法取代不落库。跨会话冲突仍需复核。
- 模型请求单次45秒超时；每次领取独立 owner；发布候选和回执前检查 owner/租约，旧 worker 被接管后拒绝发布。
- 缺 key 保留任务，不能把未提炼伪装成成功；失败任务最终归档仍保留输入。
- 在线 backupMemory 使用 SQLite backup 并验证 integrity，拒绝覆盖目标。测试覆盖 WAL 中的已提交记录；未调度生产备份。
- LoCoMo 支持预算对象、严格 yes/no 判分、仓库内模型库、显式模型凭据、全量默认、对话级 development/holdout 划分、数据/模型库摘要与原始判分输出。

## 本地证据

- npm test：原有15组套件，contracts 自动包含 tests/reliability.test.mjs。
- 新增 reliability 测试覆盖：漏记重试、消息日期、同文防复活、来源回查、在线备份、三进程并发与杀进程锁恢复、曝光/使用反馈分离、同会话证据修订与跨会话拒绝、旧 worker 发布拒绝。
- 真实双模型固定集（37题、30条记忆）仍是开发回归，不是独立留出。最初基线 Hit@5=0.8387，证据完整率0.8065，误召回条目占比0.5904。
- 一次收紧语义候选的实验降低了误召回，也丢失了一道有答案题，已撤回。不得把该实验当交付效果或独立验证。报告保存于 evidence/hardening/。
